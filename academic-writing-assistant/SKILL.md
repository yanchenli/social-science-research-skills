# 学术论文写作助手 — Introduction & Literature Review

## 核心理念

**AI辅助写作，研究者主导内容。** AI负责结构、逻辑、语言和格式；研究者负责确认论点方向、审核引用准确性、提供研究情境。

> ⚠️ **重要提醒**：AI生成的所有文献引用信息（作者、年份、期刊）必须在真实数据库（Google Scholar、Web of Science等）中核实后方可使用。

---

## 快速入口：你目前在哪个阶段？

根据用户情况（或从对话中推断）选择入口：

| 用户情况 | 进入阶段 |
|---------|---------|
| 只有研究主题/想法，尚未开始 | **阶段1** — 写作前规划 |
| 有文献清单/笔记，不知如何组织 | **阶段2** — 文献梳理与框架 |
| 有框架，开始动笔写Introduction | **阶段3** — Introduction写作 |
| 有框架，开始动笔写Literature Review | **阶段4** — Literature Review写作 |
| 有草稿，需要润色/改写/扩展 | **阶段5** — 修改与润色 |
| 有完整内容，需要输出为Word文档 | **阶段6** — 文档生成 |

---

## 阶段1 — 写作前规划

**目标**：明确研究定位，确定Introduction和Lit Review的写作策略。

### 1.1 信息收集

开始前，向用户确认（或从上下文中提取）：

| 信息项 | 说明 | 若用户未提供 |
|--------|------|------------|
| 研究主题 | 一句话描述研究在做什么 | 必须询问 |
| 研究问题/假设 | RQ或核心假设 | 询问，或在阶段2协助建立 |
| 目标期刊/论文类型 | 期刊论文/学位论文/会议论文 | 默认"期刊论文" |
| 所在学科领域 | 营销、管理、组织行为、人力资源等 | 从主题推断 |
| 写作语言 | 中文 / 英文 | 默认英文（期刊投稿）；学位论文询问 |
| 文献数量 | 用户已有多少篇参考文献 | 询问 |
| 字数要求 | Introduction和Lit Review各多少字 | 期刊：各500-1500词；学位论文：各1500-5000词 |

### 1.2 研究定位工具

使用以下模板帮助用户厘清研究定位（先内部推理，再呈现给用户）：

```
研究定位一句话框架：
"本研究探讨 [自变量/现象] 对 [因变量/结果] 的影响，
聚焦于 [情境/边界条件]，
以 [理论基础] 为理论视角，
弥补 [现有研究空白] 的不足。"
```

协助用户填写后，进入阶段2。

---

## 阶段2 — 文献梳理与框架搭建

**目标**：将零散文献整理成有逻辑的综述框架。

### 2.1 文献分类方法

根据用户提供的文献列表（或主题），按以下维度分组：

**维度A：按主题分组**（推荐用于综述导向论文）
- 主变量相关文献
- 机制/中介变量相关文献
- 情境/调节变量相关文献
- 理论基础文献

**维度B：按时间脉络分组**（推荐用于理论发展综述）
- 奠基性研究（20年以上）
- 发展期研究（10-20年）
- 近期研究（5年内）

**维度C：按研究结论分组**（推荐用于元分析式综述）
- 支持某观点的文献
- 挑战或修正该观点的文献
- 提出边界条件的文献

### 2.2 研究缺口识别

协助用户识别可论证的研究缺口类型：

| 缺口类型 | 描述 | 示例表达 |
|---------|------|---------|
| **理论缺口** | 现有理论无法解释某现象 | "Prior research has not theorized..." |
| **情境缺口** | 某结论未在特定情境中验证 | "Little attention has been paid to X in the context of Y..." |
| **机制缺口** | 知道"是什么"但不知"为什么" | "The underlying mechanism remains unclear..." |
| **边界缺口** | 未知调节变量 | "When and for whom X affects Y is largely unexplored..." |
| **方法缺口** | 现有研究方法局限 | "Previous studies relying on... may have overstated..." |

### 2.3 生成文献综述框架

基于上述分析，输出一个带层级标题的框架提纲：

```
示例框架（营销/消费者行为）：
2. Literature Review
   2.1 [核心构念A] — 定义、测量、前因后果
   2.2 [核心构念B] — 定义、测量、与A的关系
   2.3 理论基础：[理论名称]
   2.4 研究假设推导
```

框架确认后，进入阶段3或4。

## 阶段3 — Introduction写作

**目标**：撰写符合"漏斗结构"的Introduction。

### 3.1 Introduction结构（漏斗模型）

```
┌─────────────────────────────────────────┐
│  1. 宏观背景钩子（1-2句）                  │  ← 现象重要性/实践价值
│  2. 现有研究综述（2-4句）                  │  ← 文献已知什么
│  3. 研究缺口（1-2句）                     │  ← 但是/然而/不足
│  4. 本研究目的与贡献（2-3句）              │  ← 本研究做什么/贡献
│  5. 论文结构预告（可选，1-2句）             │  ← 论文如何组织
└─────────────────────────────────────────┘
```

### 3.2 各部分写作要点

**① 宏观背景钩子**
- 用统计数据或现实现象开场（需用户提供真实数据）
- 建立现象的重要性或实践紧迫性
- 英文示例结构：`"In recent years, X has emerged as a critical issue in Y, with [statistic/phenomenon] (citation)."`

**② 文献综述句**
- 概括该领域的主要发现（不展开）
- 英文过渡词：`Prior research has..., Existing studies have shown..., A growing body of work suggests...`

**③ 研究缺口**（最关键）
- 明确点出现有研究"缺什么"
- 英文缺口词组：`However, little is known about...; Despite this progress, we have limited understanding of...; Yet, whether/how/when X... remains unclear.`
- 避免过度否定前人研究，用"尽管已有贡献，但……"句式

**④ 研究目的与贡献**
- 明确说明本研究"做什么"、"用什么理论"、"在什么情境"
- 说明对理论和实践的双重贡献
- 英文结构：`"Drawing on [theory], this study examines/investigates/explores [X] in the context of [Y]. We contribute to the literature by..."`

### 3.3 Introduction写作提示词（可直接使用）

```
## 任务
帮我撰写一篇学术论文的Introduction（[中文/英文]），[期刊/学位论文]风格。

## 研究信息
- 研究主题：[填写]
- 核心研究问题：[填写]
- 理论基础：[填写]
- 研究情境：[填写]
- 主要贡献：[填写]
- 研究缺口：[填写]
- 字数要求：约 [X] 字/词

## 写作要求
- 采用漏斗结构：背景 → 文献 → 缺口 → 本研究目的
- 学术语气，客观严谨，不使用第一人称（"我"或"I"）
- 缺口段落要有力，用转折句型突出不足
- 文献引用用 [Author, Year] 占位，提示用户核实
- 不要生成虚假统计数据，用 [请填入真实数据] 占位
```

## 阶段4 — Literature Review写作

**目标**：撰写有逻辑、有深度、论点清晰的文献综述。

### 4.1 每个子节的写作结构

每个Lit Review子节遵循以下结构：

```
① 开头定义句 — 界定本节讨论的构念/概念
② 历史发展/流派介绍 — 简要梳理主要研究脉络
③ 核心研究发现综述 — 综合2-5篇代表性文献的主要结论
④ 争议或局限 — 指出该领域尚存争议或方法局限
⑤ 过渡句 — 连接下一子节或引出假设推导
```

### 4.2 综述写作原则

**批判性综述 vs. 描述性综述**

| 描述性（避免） | 批判性（推荐） |
|--------------|--------------|
| "Smith (2020) found that X affects Y." | "Smith (2020) demonstrated X→Y, but used a student sample, limiting generalizability." |
| 逐篇列举文献 | 按主题整合多篇文献 |
| 只说"做了什么" | 说明"贡献是什么"和"局限在哪" |

**综述段落结构模板（英文）**：
```
[综合性开场句，概括该主题的总体研究方向].
[引入代表性研究1，概述其核心发现] (Author, Year).
[引入研究2，说明其如何补充或挑战研究1] (Author, Year).
[综合评述：这些研究共同揭示了什么，或存在什么争议].
[过渡：但是，在[特定情境/条件]下，[尚不清楚的方面]].
```

### 4.3 假设推导写作

假设推导是Lit Review的核心，使用以下逻辑框架：

```
理论逻辑链：
前提1（理论A支撑）→ 前提2（文献B支撑）→ 因此，[假设H1]

英文表达模板：
"[理论名称] suggests that [前提1]. [文献证据] (Author, Year).
 Furthermore, [前提2/机制]. Therefore, we hypothesize that:

 Hypothesis 1: [X] is positively/negatively associated with [Y]."
```

## 阶段5 — 修改与润色

**目标**：改善现有草稿的逻辑、语言和学术规范性。

### 5.1 诊断清单（收到草稿后先执行）

| 检查维度 | 要点 |
|---------|------|
| **结构完整性** | Introduction是否有漏斗结构？Lit Review是否每节有明确主题句？ |
| **缺口论证** | 研究缺口是否清晰、可信？是否有文献支撑？ |
| **假设逻辑** | 假设推导是否有理论依据？是否能从前提逻辑推出结论？ |
| **文献整合度** | 是否有"流水账"式逐篇罗列？是否缺乏综合性评述？ |
| **语言学术性** | 是否有口语化表达？主动/被动语态是否得当？ |
| **过渡连接** | 段落之间是否有过渡句？章节之间是否有衔接？ |

### 5.2 常见问题与修复策略

**问题1：缺口论证不足**
- 症状：用"本研究将……"直接跳到研究目的，没有说明"为什么需要"
- 修复：在缺口句前增加"尽管X已有研究，但Y在Z情境下仍不明确"

**问题2：文献综述是"摘要堆砌"**
- 症状：每段只有一篇文献，逐篇介绍
- 修复：将同主题文献合并，用综合句引出，增加比较与评价

**问题3：假设从天而降**
- 症状：直接给出假设，没有逻辑推导过程
- 修复：在假设前增加"理论推导段"，展示前提→结论链条

**问题4：Introduction太长/太短**
- 期刊论文：通常400-800词（约1-1.5页）
- 学位论文：通常1500-3000字（中文）

## 阶段6 — 文档生成（.docx输出）

用所在环境提供的文档生成能力（如 `python-docx` 库或 `pandoc` 转换；若环境中已有专门的 docx 技能，优先使用它）生成 `.docx` 文件。下方的「样式规范」「文档结构」「特殊标注规范」三节作为**设计规格**交给它，不要绕过规格自行拼装文档。

### 样式规范

```javascript
const DARK_BLUE  = "1F3864";   // 一级标题（章节标题）
const MID_BLUE   = "2E75B6";   // 二级标题（子节标题）
const LIGHT_BLUE = "D6E4F0";   // 提示框/注意框背景
const GRAY_BG    = "F5F5F5";   // 引用块背景
const RED_NOTE   = "C00000";   // 核验提示（引用待核实标注）

// 字体：Times New Roman（英文论文标准）或 宋体（中文论文标准）
// 页面：A4，四边距 2.54 cm（1英寸）
// 正文字号：12pt（英文）/ 小四（中文）
// 行距：double（英文期刊标准）/ 1.5倍（中文学位论文）
```

### 文档结构

```javascript
// 典型输出结构
[封面/标题信息（可选）]
[1. Introduction]
   [正文段落...]
[2. Literature Review]
   [2.1 子节标题]
      [正文段落...]
   [2.2 子节标题]
      [...]
[参考文献占位（可选）]
[⚠️ 核验清单：所有待核实引用列表]
```

### 特殊标注规范

- 所有AI生成的文献引用，用红色标注 `[待核实: Author, Year]`，提醒用户在真实数据库中核查
- 统计数据占位符用黄色高亮标注：`[请填入：XXX的数据来源]`
- 假设编号保持与论文其他部分一致

### 生成后执行验证

```bash
python3 -c "import sys,zipfile; z=zipfile.ZipFile(sys.argv[1]); print('corrupt:', z.testzip()); print('parts:', len(z.namelist()))" ./<file>.docx
```

再用所在环境的文档工具（Office / WPS / LibreOffice 等）打开该 `.docx` 做一次视觉核对，
逐节确认标题层级、颜色分级与表格未跑版。

验证通过后：
```bash
cp ./<filename>.docx outputs/<filename>.docx
```

## 重要原则（贯穿全程）

1. **不编造引用**：所有文献引用均为占位格式，必须提示用户核实
2. **不代替判断**：研究问题、理论选择、缺口论点，AI提供选项，用户做最终决定
3. **保留研究者声音**：修改润色时，保持用户原有的核心论点，只改语言和结构
4. **分阶段交付**：每完成一个阶段，先请用户确认再继续，避免大量返工
