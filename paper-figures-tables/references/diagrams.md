# 示意图：模型描述格式与构图规则

`scripts/make_diagram.py` 吃一份 JSON 模型描述，输出 SVG。四种图共用同一套格式。

```
python make_diagram.py model.json figure.svg
```

## 一、JSON 格式

```json
{
  "lang": "en",
  "title": "Figure 1",
  "subtitle": "Proposed Model of Relationship Commitment",
  "width": 468,
  "nodes": [
    {"id": "sv", "label": "Shared values"},
    {"id": "tr", "label": "Trust", "shape": "ellipse", "level": 1}
  ],
  "edges": [
    {"from": "sv", "to": "tr", "label": "H4", "coef": ".192***"}
  ],
  "moderators": [
    {"id": "unc", "label": "Uncertainty", "on": ["tr", "cm"], "label_on_edge": "H13"}
  ],
  "controls": {"label": "Controls: firm size, tenure", "to": ["cm"]},
  "note": "Note. Dashed boxes are moderators."
}
```

| 字段 | 说明 |
|---|---|
| `lang` | `en` 用无衬线，`zh` 用宋体 |
| `width` | 画布宽（pt），默认 468（APA 整幅 6.5 in） |
| `nodes[].shape` | `box`（默认）/ `ellipse`（潜变量）/ `dashed` |
| `nodes[].level` | 列号。**不写就按最长路径自动分层** |
| `edges[].label` | 假设编号，如 `H1` |
| `edges[].coef` | 系数，如 `.53***`；与 label 同时存在时上下排 |
| `edges[].bidirectional` | `true` 时画双向箭头——潜变量之间的**相关/协方差**用它，因果路径不要用 |
| `row_gap` | 同一列相邻节点的垂直间距（pt），默认 24。**双向箭头建议 ≥ 36**，否则两根箭头背靠背、中间没有杆 |
| `moderators[].on` | 被调节的那条边的两个端点 id |
| `moderators[].position` | `above`（默认）/ `below` |
| `controls.to` | 控制变量指向哪些节点 |

## 二、四种图的画法

### 1. 概念框架图（conceptual）

只放构念与路径，**不放题项、不放系数**（系数留给结构模型图）。

```json
{"nodes": [{"id": "a", "label": "Brand trust"},
           {"id": "b", "label": "Purchase intention"}],
 "edges": [{"from": "a", "to": "b", "label": "H1"}]}
```

规则：

- 单一流向，左 → 右。不要出现左右来回的箭头。
- 调节变量**指向箭头中点**，不指向节点（见第三节）。
- 控制变量用虚线指向因变量，不编号。
- 一幅图讲一个模型，不要在一幅图里塞两个研究。

### 2. 测量模型图（measurement）

潜变量用椭圆，题项用方框，箭头从潜变量指向题项，载荷标在箭头上。

```json
{"nodes": [
   {"id": "tr", "label": "品牌信任", "shape": "ellipse", "level": 0},
   {"id": "t1", "label": "值得信赖", "level": 1},
   {"id": "t2", "label": "言行一致", "level": 1}],
 "edges": [
   {"from": "tr", "to": "t1", "coef": ".82"},
   {"from": "tr", "to": "t2", "coef": ".76"}]}
```

规则：

- 载荷统一两位小数，省略前导零（`.82`）。
- 题项超过 8 个时**不要画全模型**，改用信效度汇总表——图会挤成一团。
- 误差项默认省略；若审稿人要求，加小圆并标 `e1…en`。
- **潜变量之间是相关，不是因果**——必须画双向箭头，且**不标 H**。
  H 是方向性假设，标在相关上会自相矛盾（详见下面 2.1）。

#### 2.1 测量模型的双箭头，与结构模型的单箭头

这是两类图最容易被画混的一处：

| | 测量模型（CFA） | 结构模型（路径图） |
|---|---|---|
| 潜变量 → 题项 | 单向（载荷） | 不画题项 |
| **潜变量 ↔ 潜变量** | **双向（相关 φ）** | 不出现 |
| **潜变量 → 潜变量** | 不出现 | **单向（因果路径 β/γ）** |
| 标号 | 载荷、相关值 | H1、H2… 与路径系数 |

理由：CFA 只声明「这两个构念相关」，不声明谁影响谁。画成单向，等于在图里
偷偷加了一个方向性主张；再标上 H1，就是「用相关数据检验方向性假设」——
审稿人会直接指出这一点。

```json
{"edges": [
   {"from": "tr", "to": "t1", "coef": ".82"},
   {"from": "tr", "to": "cm", "bidirectional": true, "coef": ".53***"}]}
```

`make_diagram.py` 会检查：`"type": "measurement"` 时，若两个椭圆（潜变量）之间
的边没有 `bidirectional`，直接给出警告。双向箭头两端各留 7 pt 画箭头，
所以中间的行距不能太小——`row_gap` 取 40 时杆长约 26 pt，看起来才像一支双向箭头。

### 3. 结构模型图（structural）

潜变量用椭圆，路径标系数与显著性星号。

```json
{"nodes": [
   {"id": "tr", "label": "Trust", "shape": "ellipse", "level": 0},
   {"id": "cm", "label": "Commitment", "shape": "ellipse", "level": 1}],
 "edges": [{"from": "tr", "to": "cm", "label": "H1", "coef": ".53***"}]}
```

规则：

- 系数用**标准化**路径系数，并在图注写明。
- 星号对应水平必须在图注里给出（`*p < .05. **p < .01. ***p < .001.`）。
- 不显著的路径用虚线或灰色，并在注中说明——不要直接删掉，读者需要看到假设被检验过。
- 内生变量的 R² 标在节点右上角。

### 4. 交互效应图（interaction）

用 `make_interaction.py`，不要手画。它从数据算简单斜率，避免手抄错。

```
python make_interaction.py fig.svg --data d.csv --dv y --x x --mod m \
       --xlabel "Brand trust" --ylabel "Purchase intention"
```

规则：

- 两条线：调节变量在 **均值 ± 1 SD** 处。**不要用中位数二分**——连续变量二分
  会损失信息并人为制造显著。
- 若原始研究确实做了二分操纵（如高/低承诺两组），用 `--levels 0,1` 显式指定。
- 加 95% 置信带；两条带明显重叠时，要如实说明交互很弱。
- 线端直接标注，比图例省版面。
- 图注写明斜率或交互项系数。

## 三、调节变量：指向箭头，不指向节点

这是概念框架图最容易画错、也最容易被审稿人挑出来的一处。

```
错误：Moderator ──→ DV          读者会理解为「调节变量影响因变量」（主效应）
正确：Moderator ──→ ──────→     箭头落在 IV→DV 这条边的中点上
```

含义差别很大：调节变量改变的是**关系的强度**，不是因变量本身。
`make_diagram.py` 的 `moderators[].on` 就是为此设计的——它接受两个端点 id，
把箭头画到这条边的中点。

同理，**调节变量的编号（H2）要标在那条竖直箭头上**，不是标在主效应边上。

## 四、常见错误

| 错误 | 后果 |
|---|---|
| 调节变量指向节点 | 被读成主效应，假设类型错了 |
| 一幅图里既有构念又有题项 | 读者不知道在看哪一层 |
| 用双箭头表示因果 | 因果方向不明 |
| 控制变量也编号 H | 假设数量虚增 |
| 系数不标显著性 | 读者无法判断假设是否成立 |
| 图中出现正文没提过的构念 | 模型与叙述不一致 |
| 连线从方框里穿过，或贴着框边擦过 | 视觉上读不出路径 |
| 编号落在两条线中间 | 读者会把它读成另一条线的编号 |

## 五、连线几何：出入口、净空与交叉

连线好不好看，取决于三件可测量的事，不是「看起来还行」。

### 1. 出入口边：不是固定的，要按代价挑

早期的做法是按方向定：目标在右边就从左边进、从右边出。这会在两种情况下出错：

- 中间隔着一个方框（线要穿过去才能到达那条边）
- 同一侧挤了太多线（箭头叠在一点）

现在改成在 4×4 = 16 种「入口边 × 出口边」组合里挑代价最小的：

| 代价 | 权重 | 含义 |
|---|---|---|
| 穿框 / 贴框 | ×1000 | 线进入任何无关方框，或离它不足 10 pt |
| 交叉 | ×40 | 与已画出的线相交 |
| 贴边不足 | ×1 | 净空差额，用于在都合规时选更宽裕的 |

还额外禁止一种情况：**线钻进自己两端节点的框内**。
少了这条检查，会选出「从节点左边出、横穿自己的框、再进目标右边缘」这种线——
端点确实在框边上，但整条线从框里穿过去了。

### 2. 净空用欧氏距离，不用「轴对齐外扩矩形」

判定「线离框太近」必须用真实距离。用轴对齐外扩矩形会在方框四角偏严：
一条线离框角 11 pt 却被判成不足 10 pt，逼得选边搜索退到更差的方案。

阈值：**无关方框的净空 ≥ 10 pt**（约 0.14 in）。

### 3. 接入点要沿四条边分散

同一目标节点上的多条线如果都进同一点，会挤成一团并互相交叉。
四条边都要分散，且**出口按出发斜率排序**（平缓的在上、陡的在下）——
只按目标 y 排序时，两个目标同高就退化成任意顺序，同一个节点引出的两条线
会在框外立刻交叉。

### 4. 编号的归属必须可判定

一个编号只能被读成「它旁边那条线」的编号。判据是两条：

- 离自己那条线 **≤ 17 pt**
- 离自己那条线，比离**任何别的线**近 **≥ 3 pt**

第二条最容易被忽略：H10 标在两条平行线之间，两边距离 9.0 与 8.0，
读者会把它读成更近的那条。宁可把编号贴得更紧，也不能让它漂到中间。

短线（< 45 pt）没有空间放 14 pt 的偏移，收紧到 9 pt。

## 六、交付前检查：规格 + 几何两道

| 脚本 | 查什么 | 输入 |
|---|---|---|
| `check_figure.py` | 图宽、字号下限、线宽、竖线、表头底线、残留空 run、前导零 | `.svg` / `.docx` |
| `check_connections.py` | 净空、穿自己框、线线交叉、编号归属、编号重叠、箭头落点 | `.geo.json` |

几何检查需要先导出快照：

```bash
python scripts/make_diagram.py spec.json out.svg --geometry out.geo.json
python scripts/check_connections.py out.geo.json
```

快照里是每条边的完整路径、每个编号的归属、调节变量箭头的位置。
**检查脚本读的是生成器自己算出来的坐标**，不是从 SVG 反推——
反推需要「拿折线端点去配箭头」，配错一次就会报出不存在的交叉。

### 交叉怎么处理

密集模型里交叉往往无法完全消除。判断标准不是「有没有交叉」，而是
**能不能通过换行序消掉**。用 `--geometry` 导出的数据可以穷举行序试一遍：
实测一个 10 节点 11 边的模型，原始行序 2 处交叉，120 种行序里最少 1 处。

如果调行序也降不下来，说明交叉是模型结构决定的，这时应该考虑拆成两幅图
（比如把调节效应单独画一幅），而不是继续在布局上打转。

## 七、渲染与导出

生成的 SVG 是矢量，可直接：

- 插入 Word（插入 → 图片，Word 会保留矢量）
- 用 Inkscape / Illustrator 打开转 PDF 或 EPS（多数期刊要求 EPS/PDF）
- 浏览器打开后打印为 PDF

**不要截图转 PNG 再插入**——位图放大会糊，期刊通常要求 300 dpi 以上或矢量。
