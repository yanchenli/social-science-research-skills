# 多系列折线图规格

一个文件画 N 条线，每条可带置信带。交互效应图（`make_interaction.py`）用的是同一段画图代码，
所以这两处的几何规则是一致的。

```bash
python scripts/make_line_plot.py fig2a.svg spec.json
python scripts/make_line_plot.py fig2a.svg spec.json --export pdf,png --dpi 600
python scripts/make_line_plot.py out.svg --data d.csv --x stage --y mean --by group
```

---

## 一、规格字段

| 字段 | 说明 |
|---|---|
| `series` | **必填**。`[{label, x, y, lo?, hi?}]` |
| `xlabel` / `ylabel` | 轴标题。**两条都要写**——只写一条等于让读者猜另一个是什么量 |
| `y_range` / `x_range` | `[下界, 上界]`。有自然边界的量（李克特、百分比、相关系数）**必须给** |
| `x_ticks` | `[{v, label}]`。分类轴（阶段、组别）用；不给就按数值自动取刻度 |
| `refline` | `{axis: "y"|"x", v, label?, label_pos?, label_side?}` |
| `legend` | `"end"`（默认，线端标注）/ `"top"`（绘图区上方横排）/ `"corner"` / `"none"` |
| `markers` | `true` 时每条线加标记形状 |
| `note` | 图注，画在画布底部 |
| `width` / `height` | 画布尺寸（pt）。默认 468 × 190 |

### series 里的字段

| 字段 | 说明 |
|---|---|
| `label` | **必填**。线端标注或图例都靠它；重复会报错 |
| `x` / `y` | 数值数组，长度必须相同 |
| `lo` / `hi` | 置信带的两端。**必须同时给**——只给一半画不出来，脚本直接报错 |
| `dash` | 覆盖默认线型，如 `"5 2.5"` |
| `marker` | 覆盖默认标记：`circle` / `square` / `triangle` / `diamond` |

---

## 二、为什么不用颜色

黑白印刷会把三种彩色印成三条一样的灰线。默认按顺序分配：

| | 线型 | 标记 |
|---|---|---|
| 第 1 条 | 实线 | 圆 |
| 第 2 条 | 长虚线 `5 2.5` | 方 |
| 第 3 条 | 点线 `1.6 1.6` | 三角 |
| 第 4 条 | 点划线 `6 2 1.5 2` | 菱形 |

**图例不要放进绘图区。** `"corner"` 把图例摆在右上角，而折线的右上角往往正是终点所在——
第一次复刻就撞上了。`"top"` 在绘图区上方横排，一行放不下会自动折行，是唯一不会压住数据的位置。

**超过 4 条要重新想**：不是加线型，而是问「这四条真的该在同一张图里比吗」。
规格校验会提示。

---

## 三、纵轴范围是最常错的一处

不给 `y_range` 时按数据范围自动缩放，两端各留 8%。对李克特量表这是错的：

```
数据 3.8 – 4.4，自动缩放后纵轴从 3.75 到 4.45
```

读者看到的是「差异很大」，实际只是 7 点量表里 0.6 的差距。给了 `y_range: [1, 7]`
才看得出这几条线其实都在量表中点附近。

规格校验在检测到「数据都在 2.5–7 之间」时会提示补 `y_range`。这只是启发式——
0–1 的比例、相关系数同样需要显式范围，脚本猜不出来。

---

## 四、置信带怎么画

`lo` / `hi` 给的是**该点估计值的区间**，不是标准差。带子用 8% 灰填充、无描边。

三条线的带子会互相重叠，看起来会发灰。这不是 bug：重叠本身就是信息
（说明这几条线在该点分不开）。要更清楚就把面板拆开，或者只画关键那一条的带子。

**不要用「两条线的带子是否重叠」判断差异是否显著**——重叠与否不是差异检验，
要看交互项或组间对比的检验结果。
