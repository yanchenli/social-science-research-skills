# response-to-reviewers

> 审稿意见回应助手 —— R&R 不是改文章，是让编辑相信每一条都被认真对待了。

**版本**：1.0.0 ｜ **适用**：投稿中的商科 MS/PhD/DBA 学生及教师 ｜ **规模**：SKILL.md（单文件）

---

## 它解决什么问题

收到 Revise & Resubmit 的那一刻，多数人面对的是两份甚至三份互相矛盾的意见、一堆不知道该不该照做的要求，以及「这样反驳会不会太冲」的不确定。

这个技能做三件事：

1. 把散乱的意见整理成一张可逐条追踪的清单；
2. 为每一条选定应对策略（而不是凭情绪决定）；
3. 写出可直接随修改稿提交的回复信。

---

## 核心理念

**回信是写给编辑看的，不是写给审稿人看的。**

编辑才是做决定的人。回信的任务是让编辑**不用重新翻审稿意见**，就能确认每一条都被认真处理了。

> **范围提醒**：本技能处理的是收到 R&R（修改后再审）之后的回应。
> 如果论文已被**拒稿**、想申诉编辑决定，那是另一种文体（appeal letter），
> 逻辑与策略都不一样，**不在本技能范围内**。

---

## 工作流程（五阶段）

| 阶段 | 内容 |
|---|---|
| 1. 意见整理与分类 | 标注来源、类型（实质 / 编辑性）、所属章节 |
| 2. 逐条应对策略 | 四选一，见下 |
| 3. 回信撰写 | 结构、开场、语气 |
| 4. 审稿人意见冲突 | 摆到台面上，请编辑裁决 |
| 5. 交付 | 生成正式回信 `.docx` |

### 阶段 1 的一个关键动作

按**论文的部分**（Intro / 方法 / 结果 / 讨论）归类，而不是死板地按审稿人编号。

两个审稿人常常用不同的话讲同一个问题。归到一起处理，回信里可以合并说明，也不会漏。

### 阶段 2 的四类策略

| 策略 | 什么时候用 |
|---|---|
| 完全采纳 | 审稿人是对的，照做 |
| 部分采纳 + 说明 | 部分合理，但完全照做会带来别的问题 |
| 礼貌但坚定地不同意 | 审稿人理解有误，或建议与研究设计的根本逻辑冲突——**用证据反驳，不用态度反驳** |
| 提请编辑裁决 | 两位审稿人要求互相矛盾，无法同时满足 |

## 两个容易被忽略的技巧

**一、不同意也要留痕。**

即使是「礼貌但坚定地不同意」的情况，也尽量在正文里加一句澄清性补充，而不是一个字不改。
这样下一个读者（包括未来的审稿人）不会再产生同样的误解。真正「完全不能做任何调整」的情况很少。

**二、真做不到就老实说。**

不要假装做了。说明为什么做不到，然后正式承认这是研究的边界／局限——这一步直接对接
[`discussion-conclusion-writer`](../discussion-conclusion-writer/) 阶段 4 的局限性写法。

假装采纳而实际没改，是 R&R 里最伤信誉的一件事。

## 使用示例

```
审稿意见回来了。Reviewer 1 说理论框架太窄，建议加一个竞争理论；
Reviewer 2 说理论太多、要聚焦单一理论以增强内部一致性。
还有一条说样本量太小，但我们没法再收数据了。
帮我整理并起草回复信，英文。
```

技能会做四件事：把三条意见归类（两条其实是同一个「理论范围」问题但方向相反）、
指出这是**审稿人之间的冲突**需要明确请编辑裁决、为「样本量」那条给出「承认局限」而非
「假装补做」的写法，最后按审稿人分组生成回信。

---

## 边界与注意事项

- **不替你决定要不要照做。** 策略选项与后果由技能给出，拍板的是研究者。
- **不虚构已做的修改。** 若你尚未真正修改，技能会要求你先改，或改写成「承认局限」。
- **不管 appeal letter。** 拒稿申诉是另一种文体，见上文范围提醒。
- **语气不设「强硬模式」。** 全程礼貌、不防御——审稿人是在批评论文，不是在针对你。

## 与相邻技能的分工

- 想知道「我的论文会被怎么挑刺」→ 用 [`management-paper-reviewer`](../management-paper-reviewer/)。
  两者是一体两面：那个帮你挑刺，这个帮你在意见回来后逐条回应。
- 需要把局限写成正文 → 用 [`discussion-conclusion-writer`](../discussion-conclusion-writer/) 阶段 4。
- 意见里涉及统计质疑、要重新报告结果 → 用 [`stats-results-writer`](../stats-results-writer/) 或
  [`quant-data-analysis`](../quant-data-analysis/) 重跑。
