# 共同计划与决策管理

配合`SKILL.md`阶段0、2、5使用。所有数据路径共用这一份。

## 1. 两个维度，决定要做哪些模块

数据来源和研究目的是两回事。同一份既有问卷数据，既可以做确认性检验，也可以做探索。先分别判断，再组合：

| 数据路径 | 对应分支文件 |
|---|---|
| 一手量化（问卷、实验） | `primary-quantitative.md` |
| 一手质性（访谈、观察） | `primary-qualitative.md` |
| 二手结构化数据（交易记录、企业数据库、公开统计） | `secondary-structured.md` |
| 二手文本与数字痕迹（平台帖子、评论、点击日志） | `secondary-structured.md`末尾的简要检查（完整模块在第二版） |
| 混合 | 各自分支＋阶段2里写明整合逻辑（完整模块在第二版） |

| 研究目的 | 事前锁定的要求 |
|---|---|
| 确认性检验 | 严：关键假设、核心变量、样本规则、主要分析、排除规则都要事前锁定 |
| 预测或分类 | 严在数据划分与信息泄漏防范：训练/验证/测试的用途事前定，测试集封存 |
| 探索性发现、理论建构、质性 | 松：记录初始设计、允许调整的范围、每次调整的时间与理由，不要求冻结最终主题或编码框架 |
| 测量开发 | 中：条目池、预试与正式样本的分界事前定 |
| 描述性研究 | 中：总体、指标定义与口径事前定 |
| 混合目的 | 逐项决策分别标记属于确认还是探索 |

组合示例：一手问卷＋确认性检验，重点是抽样、量表、排除规则、主要假设；二手交易记录＋确认性检验，重点是数据生成机制、变量构造、样本选择、时间窗口、分析自由度；二手数据＋预测建模，重点是数据划分、泄漏防范、测试集保护。

## 2. 数据接触审计（Data Exposure Audit）

二手数据研究者往往在形成假设之前就看过数据。真正要管理的不是"看没看过"，而是**哪些决定是在看到相关结果之前定下的，哪些是之后才形成的**。查看数据结构不等于查看结果；看了结果也不意味着研究失去价值，只意味着相应的决定要如实标记。

先问研究者：

1. 接触过哪些数据集、变量、样本或时间段？
2. 看过哪些统计信息或图表（分布、相关、趋势）？
3. 是否已经检验过研究假设、跑过回归、做过变量筛选？
4. 已经看到的内容，是否影响了研究问题、样本限制、变量定义或分析策略？
5. 哪些决定仍然能合理地视为事前决定？

按答案归入接触等级（**本skill的操作性分级，不是学术界的统一标准**）：

| 等级 | 含义 |
|---|---|
| E0 | 尚未接触：只有研究问题、理论或数据来源设想 |
| E1 | 了解来源与元数据：查过数据说明、变量目录、获取条件，没看具体记录 |
| E2 | 查看结构或有限样本：看过字段、数据结构、有限样本或初步质量剖面 |
| E3 | 查看完整数据或描述性结果：看过分布、相关、时间趋势，但没做目标假设检验 |
| E4 | 做过假设相关分析：模型估计、显著性检验、变量筛选或结果驱动的规格调整 |

登记（如OSF）时，把等级翻译成对方表单要求的表述；OSF的预注册表会询问注册时间点与数据接触情况，具体选项以OSF当前表单为准，登记前对照核对。OSF另有专门面向既有数据的预注册模板（van den Akker等，发表于*Meta-Psychology*，作者与卷期引用前待核对）。

**每次运行`scripts/profile_dataset.py`都会升级接触等级**（`structure`级别→至少E2，`full`级别→至少E3），并写入`exposure_log.jsonl`。要保持结果变量盲化，必须在运行前通过`--outcome-vars`指定。

## 3. 决策状态与证据状态

每项关键决定（变量定义、样本规则、分析计划……）标两个状态：

**decision_status：这个决定什么时候、怎样定下来的**

| 值 | 含义 | 处理 |
|---|---|---|
| `pre_locked` | 在接触相关结果数据之前确定 | 纳入确认性计划 |
| `locked_after_exposure` | 已看过结构或描述信息，但在任何假设相关分析之前确定 | 如实披露接触程度 |
| `data_driven` | 观察数据或初步结果之后形成 | 标记为探索性或数据驱动 |
| `open` | 信息不足，尚无法确定 | 记录待解决问题与解决条件 |

**evidence_status：这条信息核实到了什么程度**

| 值 | 含义 |
|---|---|
| `researcher_stated` | 研究者陈述 |
| `source_documented` | 官方文档确认 |
| `profile_verified` | 数据剖面验证 |
| `needs_verification` | 仍待核实 |

两个状态都不是对数据质量的评分。**下游使用者不能因为计划书写得完整，就把`needs_verification`或`researcher_stated`的内容当成已验证。**

## 4. 冻结基线，有记录的变更

计划书不是一份不能改的文件，而是一个带日期的基线加上变更记录：

- **基线（V1.0）**：研究问题、假设、数据来源、样本规则、变量操作化、主要分析、伦理安排，注明日期、作者、数据接触等级
- **变更**：每次调整在决策日志里**新增一行**（不覆盖旧行）：日期、原定方案、新方案、原因、调整时是否已接触相关结果（`exposure_at_time`）、对结论可能的影响、是否需要重新登记
- **最终报告**：区分原定分析、经记录调整的分析、事后探索性分析

质性与探索性研究允许根据材料调整，关键是**记录**，而不是禁止。

## 5. 研究目标、构念与估计目标（轻量写法）

- **目标人群、分析单位、研究场景**各一句话
- **研究类型**：描述、预测、解释、因果识别还是理论建构
- **目标估计量（大白话）**：确认性的解释或因果研究要写——"比较谁、比较什么、在什么时间范围"。描述和探索性研究不要求
- **构念—测量—字段映射卡**（每个核心构念一张）：理论定义 → 操作性定义 → 观测指标 → 原始字段 → 计算方式 → 替代测量 → 已有信效度证据。营销研究尤其要防止把指标名当构念：购买次数不等于忠诚，互动次数不必然代表品牌参与，预测准确率也不能证明理论解释正确

## 6. 抽样框架与数据生成机制

区分三层：**理论上想研究谁 → 实际可接触的总体 → 最终进入分析的样本**。然后问：

- 谁进入了数据，谁没有？这种差异是否与研究变量有关？
- 非应答、流失、幸存者偏差、平台自选择、进入机制
- 观测单位与分析单位是否一致

对二手数据，更要问：**数据为什么存在、为什么被记录，什么因素决定一条记录能被观察到。** 这通常比检查缺失值更重要。

## 7. 既有数据的三种手段

在二手数据研究里控制分析自由度，有三种手段，按研究目的选，**不要默认全用**：

| 手段 | 做法 | 适合 |
|---|---|---|
| 盲化汇总统计 | 在接触前指定结果变量，剖面里不对它们给出分布或趋势 | 确认性检验，且尚未看过结果 |
| 留出验证样本 | 事先封存一段数据（如样本外时间段），主分析结束后才用一次 | 预测与模型选择、有天然时间顺序的任务；封存必须在接触结果之前执行，只在计划里写"留最后20%"不算数 |
| 披露接触并把相关分析定位为探索性 | 如实写出接触情况，标记数据驱动的决定 | 已经看过结果（E3–E4）时 |

留出样本会减少可用观测，也不一定解决分析灵活性，所以不是通用要求。

## 8. 预先规定的分析项（执行归分析skill）

计划里需要有这些项目，**实际执行交给`quant-data-analysis`等分析skill**，本skill只保证它们不会从准备阶段消失：

- 缺失数据的定义、可能机制、预定处理方法
- 离群值的识别规则与保留/排除原则
- 样本排除、重复记录、异常答题规则
- 主要分析、次要分析、稳健性检验、异质性分析、探索性分析的区分
- 多重检验、模型选择、协变量选择
- 模型假设不满足时的替代方法（预设的条件分支）

## 9. 准备状态（不是数据质量评级）

| 状态 | 含义 |
|---|---|
| `ready` | 可进入数据获取或分析 |
| `ready_if_conditions_met` | 满足所列条件后可进入 |
| `blocked` | 当前存在阻碍（如无法获得授权、关键变量缺失） |
| `insufficient_evidence` | 证据不足，暂无法判断 |

判断依据：数据获取可行性（来源、渠道、成本、许可）、研究可行性（数据对研究问题的支持点与缺口）、数据质量（有证据支撑的风险，不做笼统认证）、计划是否涵盖必要决策。

## 10. 轻量模式与完整模式

- **轻量模式**（小型学生项目、单一路径、确认性设计简单）：只走阶段0、2、5，工作簿只填说明页、变量字典、决策日志
- **完整模式**：七个阶段全走，工作簿全部填写
- 切换条件：涉及二手数据、个人信息、多数据源、需要对外登记时，用完整模式
