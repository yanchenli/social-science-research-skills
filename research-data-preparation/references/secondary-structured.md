# 二手数据准备（结构化数据为主）

配合`SKILL.md`阶段1、3使用，先读`core-plan-and-decisions.md`。这是现有skill组合里此前完全空白的一块，所以检查项目最细。

## 1. 数据存在，不代表适合这个研究问题

每一项都要回答"数据实际是什么"，而不是"数据名字叫什么"。

### 1.1 来源与获取可行性（三层证据，不要混）

| 层次 | 问什么 | 证据 |
|---|---|---|
| 产品存在 | 官方是否有这个数据产品？ | 官方网页、数据目录、文档链接＋核验日期 |
| 访问权限 | **当前账户或机构**实际能否访问？ | 登录验证、订阅记录、申请批复 |
| 支持本研究 | 变量、范围、粒度是否足以回答研究问题？ | 对照变量字典与剖面结果 |

"官方网站有这个数据库"不等于"我们有权限"，也不等于"它能回答我们的问题"。每次使用本skill时，对每个拟用来源**现场联网查官方入口并填一张证据卡**（见第8节），标核验日期，查不到的写"未核实"，不要从记忆里写数据产品的内容。

### 1.2 获取成本与可达性（轻量）

时间、费用、授权、预期样本量、招募或合作难度、技术依赖、数据稳定性、备选方案。需要商业数据库、企业合作、电商平台数据或多轮访谈的项目，这一项要在早期做，理论上最合适但实际取不到的数据不应在后期才发现问题。

## 2. 构念效度：数据实际测的是什么

为每个核心变量建一张构念—测量—字段映射卡（见`core-plan-and-decisions.md`第5节），并回答：

- 观测指标与理论构念之间差多远？（交易记录当"忠诚"、点击当"兴趣"、评分当"满意"）
- 变量的单位、时间基准、计算公式、转换规则、分类依据
- 多个指标合成指数时的权重、标准化与聚合方法
- 有没有更贴近构念的替代测量？
- 指标之间是否存在**机械耦合、定义重叠、循环定义或结果变量泄漏**

## 3. 数据生成机制与样本选择

- 谁进入了数据，谁没有？进入机制是否与研究变量有关？
- 记录为什么被记录（交易发生才有记录，则没有交易的人不在数据里）
- 为了构造变量而做的样本限制（如要求有历史购买才进入样本）会不会让结果或调节变量被选择性保留？
- 目标总体、数据覆盖的总体、最终样本之间的差异要写出来

## 4. 时间窗口与结构性断裂

- 数据覆盖的区间内，有没有外部事件、政策或平台口径变化造成的断裂？（用`profile_dataset.py`看月度记录数；它只能提示线索，不能解释原因）
- 窗口怎么选，**在看结果前**写下理由：为什么这一段，为什么不是别的
- 平台政策、字段定义、统计口径是否中途改变？历史数据是否被修订过？
- 若某段时间被判定为异常，处理方式（剔除、单独分析、加控制）要在计划里事先写明

## 5. 机械关系与阈值：两个最容易被忽略的陷阱

**机械关系检查**：变量构造本身是否让假设"几乎必然成立"或"几乎不可能成立"。例如，一个人已购买的品类数量，在算术上限制了他还能新增多少品类（机会集上限）；若分析"品类广度对品类扩张的影响"，需要把总品类数或机会集作为控制或在结果解读中单独检验这一上限。

**阈值与窗口先于结果**：历史期多长、"活跃用户"门槛是多少、至少几次购买才纳入——这类选择在看结果前定死。**如果发现收紧阈值会让结果更显著，这是警讯，不是证据**：说明结果可能对这些任意选择敏感，应报告所有合理阈值下的结果，而不是只报最显著的那个。

## 6. 数据合并与粒度

- 每张表的观测单位是什么？合并后是否出现一对多膨胀（同一用户重复进入）？
- 合并键是否唯一？未匹配的记录有多少，是否与研究变量有关？
- 分析单位是否与观测单位一致；多条记录属于同一个体时，是否处理聚类

## 7. 缺失、修订与可复现

- 缺失的机制：随机缺失、与某些变量相关的缺失，还是结构性缺失（某段时间字段根本没记录）？
- 数据版本、提取日期、历史修订记录；原始文件的哈希值（剖面脚本会记录）
- 数据处理流水：从原始文件到分析数据的每一步都要能重现

## 8. 数据来源证据卡

每个拟用来源一张，**使用时现场核验**，保存在数据工作簿的"Data Acquisition"表：

| 字段 | 内容 |
|---|---|
| 来源名称 | 正式名称、发布机构或平台 |
| 官方入口 | 官方网页、数据目录、申请页面或API文档 |
| 数据内容 | 变量范围、时间跨度、地域覆盖、分析单位 |
| 获取方式 | 公开下载、付费订阅、申请授权、合作获取 |
| 使用条件 | 许可、费用、用途与分享限制 |
| 产品存在已核验？ | 是／否＋核验日期 |
| 账户有访问权限？ | 是／否／未核实 |
| 支持本研究已核验？ | 是／否／未核实（依据） |
| 已知限制 | 覆盖缺口、测量变化、历史修订、质量风险 |
| 版本与提取日期 | |
| 复核日期 | 下次复核日期 |

## 9. 可行性剖面：先看结构，再决定要不要继续

```
python scripts/profile_dataset.py --file sample.csv --current-exposure E1 \
       --id 用户ID --time 日期 --outcome-vars 结果变量 --level structure
```

- **运行前**先确认当前接触等级，并**在运行前**指定要盲化的结果变量
- `structure`级别只看结构、缺失、重复、记录数随时间的变化，不看分布；`full`级别加上非结果变量的分布和缺失漂移
- 剖面只给**证据和线索**，不判断数据"好"或"坏"，也不检查变量是否真的测量了你的构念
- 输出里的风险线索（重复记录、一个ID多条记录、月度记录数异常、缺失率漂移）用来填计划里的`evidence_status`和风险记录
- 大文件先用抽样提取运行；脚本默认只读，不修改原始数据

固定样本下"能检出多大效应"：

```
python scripts/mde_fixed_sample.py two-group --n1 300 --n2 280
```

二手数据样本量是固定的，所以用最小可检测效应来描述设计的灵敏度。**这不是事后功效**，不能用观察到的效应去反推；有聚类或重复观测时，要用独立单位数而不是行数。样本大不等于设计有效：选择机制、测量误差、聚类结构、时间依赖和混杂仍然会影响推断。

## 10. 合规与伦理（识别风险，不下结论）

数据使用条款是否允许研究使用、保存、分享；个人信息与再识别风险；爬取是否违反平台规则；是否需要伦理审批或豁免。统一在`governance-and-dmp.md`处理，结论放进`items_needing_human_verification`由人工核验。

## 11. 附：文本与数字痕迹数据的简要检查（完整模块在第二版）

平台上的可观察内容，往往只是实际行为和表达的一部分。第一版先问这几件事：

- **平台语境**：内容出现在什么平台、什么场景，推荐机制或可见性规则如何影响哪些内容被看到
- **数据获取方式与时间**：官方API、第三方数据、自行抓取？抓取日期？平台条款是否允许？
- **内容缺失**：删帖、封号、审核造成的缺失是否与研究主题相关
- **用户与内容的关联**：能否由公开内容反推出个人？是否需要去标识化
- **构念效度**：点赞、转发、评论词频等指标是否真的等于研究构念
- **伦理**：公开不等于可以随意使用；需要伦理审批的判断归人工

文本分析方法本身（编码、主题分析）归`qualitative-research-methods`或相应的分析skill。
