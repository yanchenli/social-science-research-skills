# 一手量化数据准备（问卷与实验）

配合`SKILL.md`阶段3使用，先读`core-plan-and-decisions.md`。

## 分工

本skill**不重新设计实验**。`social-science-experiment-designer`负责设计、随机化方案和功效分析，`scale-research`负责量表选择与改编；本skill接过它们的输出，转成**可执行的搭建规格**和实施记录。上游产出的SOP、预注册文档、功效分析结果是主要输入，缺哪项就先回去补。

## 1. 搭建规格（交给人或问卷连接器执行）

| 项目 | 要写清楚的内容 |
|---|---|
| 随机化 | 随机分配方案、随机化单位（个人／批次／页面）、分配比例、如何记录分配结果 |
| 问卷结构 | 模块、题目顺序、逻辑跳转、各条件下展示的内容 |
| 变量命名与赋值 | 每题的变量名、取值编码、反向计分标记、缺失值编码（与工作簿的变量字典一致） |
| 注意力检查与操纵检验 | 放在哪里、通过标准；**排除规则在数据收集前写定** |
| 质量控制 | 重复作答、机器人或异常作答、作答时长过短的识别规则，**事前定** |
| 预试 | 样本量、检查项目、问题分类、修改记录 |
| 招募与筛选 | 渠道、筛选条件、配额、报酬、同意与退出方式 |
| 样本量依据 | 来自功效分析的目标样本量及其假设（引用上游，不在这里重算） |
| 导出格式 | 文件类型、变量名、编码，确保能被`quant-data-analysis`直接读取 |

若已连接问卷类连接器，可以据此直接搭建；没有连接器时，输出人工搭建清单，由研究者在自己的平台上操作。无论哪种，**平台上线前先做一次验收**（见第4节）。

## 2. 预试与正式研究的边界

预试的价值在于发现问题，不在于增加样本。事先写明：

- 预试数据**是否并入**正式样本？默认不并入
- 预试后修改了题项或流程，是否需要重新收集？若修改影响了操纵或测量，需要
- 修改是否影响原先的注册计划？影响的话，在决策日志里新增一行，记录修改与原因

## 3. 停止规则：不要边看边停

"数据收集到什么时候停"是一个会放大假阳性的决定。在收集前写定：

- **固定样本量**（最常见）：达到N份有效回答即停，N来自功效分析
- 或预先登记的**序贯停止规则**：用经过设计的序贯方法，不是"看着差不多显著就停"
- 达到目标前**不对结果变量做中期查看**；若必须检查数据质量，只检查完成率、设计问题，不看结果

记入工作簿"Sample & Rules"的停止规则栏，以及决策日志。

## 4. 上线前验收（dry run）

用10份左右的测试作答完整走一遍，检查：

- 随机分配是否按预期执行、各条件人数是否合理
- 逻辑跳转是否正确，各条件下展示的内容是否对
- 导出文件的列名、编码、缺失值与变量字典是否一致
- 注意力检查与计时变量是否被正确记录
- 同意与退出流程是否可用

验收通过的测试数据**必须在正式数据中删除**，并在记录里写明。

## 5. 收集中的记录

同意数、退出数、最终有效样本量、各条规则排除的人数；这些数字要能和`quant-data-analysis`的N变化流水对上：总收集N → 各规则排除 → 最终N。

## 6. 数据导出与交接

导出原始数据后**先备份一份不改动的副本**，再做清理。交接给`quant-data-analysis`时附：研究数据规格（含决策状态与接触等级）、变量字典、排除规则、停止规则及实际收集记录。数据收集期间若偏离了计划，写进决策日志，不要事后在分析里悄悄调整。

## 7. 伦理与同意

同意书内容与实际数据处理方式必须一致：数据存放在哪、谁能访问、是否使用第三方平台或转录服务、保留多久。把涉及第三方处理参与者数据的事项列入`items_needing_human_verification`。
