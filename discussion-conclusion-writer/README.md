# discussion-conclusion-writer

> Discussion 与 Conclusion 撰写助手 —— 把「我们发现了什么」讲成「所以呢」。

**版本**：1.0.0 ｜ **适用**：商科 MS/PhD/DBA 学生及教师 ｜ **规模**：SKILL.md + 1 个 references

---

## 它解决什么问题

论文最容易「烂尾」的地方在这里：结果讲完了，理论贡献却讲得含糊。审稿人最常见的拒稿理由之一是「贡献不清楚」，而不是「方法有问题」。

这个技能补的是写作链条上唯一断掉的一段：

| 章节 | 负责的技能 |
|---|---|
| Introduction / Literature Review | `academic-writing-assistant` |
| Results | `stats-results-writer` |
| **Discussion / Conclusion** | **本技能** |

三段合起来，一篇论文从开头到结尾才真正闭合。

---

## 核心理念

**Discussion 不是复述 Results，是回答「所以呢」（So what）。**

结构上它是 Introduction 的倒漏斗：Introduction 从大问题收窄到具体假设，Discussion 反过来——从具体发现出发，逐步放大到理论、实践与领域的意义。

> ⚠️ AI 搭结构、套框架；**「这个发现到底重不重要」「贡献故事怎么讲才有说服力」，是研究者的判断，AI 不替你拍板。**

---

## 工作流程（五阶段）

| 阶段 | 目标 | 产出 |
|---|---|---|
| 1. 结果综合与定位重访 | 把发现放回「最初为什么做这个研究」的框架 | 一句话综合（不用假设编号复述） |
| 2. 理论贡献阐述 | 把「我们发现了 X」讲成「这对理论意味着什么」 | 贡献陈述 |
| 3. 实践与管理启示 | 翻译成对管理者有用的东西，不是正确废话 | 实践启示段落 |
| 4. 边界条件、局限与未来研究 | 诚实但不自我拆台 | 局限与未来方向 |
| 5. 结论段落与交付 | 呼应开头的钩子 | 结论段 + `.docx` |

## 三个可查的框架

不是自己编的清单，都有出处：

- **Whetten (1989) 的七个问题** —— What's new / So what / Why so / Well done / Done well / Who cares / Why now。原本用来评估理论贡献，反过来是很好的自查清单：哪几条答不上来，就是贡献没讲清楚的地方。
- **Corley & Gioia (2011) 的 2×2** —— 原创性（渐进 vs 颠覆）× 实用性（学术 vs 实践）。渐进式贡献一样有价值，但要知道自己在哪个格子里，话术不同。
- **Bartunek & Rynes (2010)** —— 实践启示要写清楚：给谁看、具体建议是什么、为什么这条建议是从「这个具体发现」推出来的。

---

## 一个很好用的自查

把写好的实践启示贴到**另一篇完全不同主题的论文**后面，读起来会不会一样通顺？

如果会，说明写得太通用——它没有从你自己的发现里长出来。

同样的检验适用于局限与未来研究：「未来应该用更大样本验证」这种句子，放在任何论文后面都成立，价值不大。好的未来方向是「因为我们发现了 X，所以现在有个新问题 Y 值得研究」。

## 使用示例

```
Results 都写完了，H1 支持、H2 不支持，H3 的调节只在女性样本里显著。
Introduction 里我提的缺口是「品牌拟人化在 B2B 情境下没人研究」。
帮我写 Discussion，中文。
```

技能会先做结果与定位的对表（原来说要填的缺口真的填上了吗？部分填上？有没有意外结果？），
再逐阶段推进。**H2 不成立这件事不会被藏起来**——意外结果往往是最有讨论价值的部分。

## 边界与注意事项

- **不脱离原始定位空谈贡献。** 贡献必须能对应回 Introduction / 文献综述里提出的具体缺口。
- **不用「支持了理论 X」当贡献。** 验证不等于贡献；真正的贡献要讲清楚「因为有了这个发现，理论 X 现在需要被怎么修改／扩展／限定」。
- **不写放之四海皆准的局限。** 见上面的自查。
- **不替研究者判断故事怎么讲。** 给框架和清单，取舍权在研究者。

## 与相邻技能的分工

- 还没理清缺口 → 用 [`literature-gap-synthesizer`](../literature-gap-synthesizer/)。
  它产出的定位陈述与本技能的「阶段 1 定位重访」是同一套模板，可以直接对接。
- Introduction 还没写 → 用 [`academic-writing-assistant`](../academic-writing-assistant/)。
  阶段 5 的结论段要呼应 Introduction 的钩子，可以直接调出当初写的那一段。
- 收到审稿意见、要写回应 → 用 [`response-to-reviewers`](../response-to-reviewers/)。
  它处理「真做不到的要求」时会指向本技能的阶段 4（局限性写法）。
