# 从现象到研究问题 — From Phenomenon to Research Question

> 不急着找答案。先把问题磨到足够深、足够有结构、足够可检验。

## 这个技能在链条的哪个位置

它是**最前端**。下游三个技能都以「你已经有一个构念/假设了」为前提：

| 技能 | 它的起点 | 它要用户提供什么 |
|---|---|---|
| **本技能** | 一个模糊的观察 | 「最近什么现象让你困惑」 |
| `literature-gap-synthesizer` | 一个**宽泛主题/构念** | 「研究主题：一句话描述」 |
| `social-science-experiment-designer` | 一个**研究想法与假设** | 「请陈述研究背景、理论和核心假设」 |
| `academic-writing-assistant` | 要**动笔写**了 | Introduction 的素材 |

**现象 → 构念 → 问题 → 假设 → 设计**，这条链上前四步归本技能，第五步交给下游。

## 核心理念

| 原则 | 含义 |
|---|---|
| **现象先于构念，构念先于假设** | 跳过前两步直接想假设，做出来的是"文献里已有结论的又一次验证" |
| **压力测试优于快速建构** | 真正的洞察不在于快速解释一个现象，而在于建一个经得起反复追问的结构 |
| **不预设学科** | 同一个现象可能同时属于营销、OB、信息系统、金融。先问"谁在研究它"，不要先贴标签 |
| **不预设方法** | 定量还是定性由问题性质决定，不是由学生偏好或导师偏好决定 |
| **"不值得研究"是合格产出** | 现象不成立、规模太小、无法观察时，如实说出来，比硬凑一个题目负责 |

## 快速入口：你现在带着什么来

| 你带来的 | 进入 |
|---|---|
| 一个模糊的观察 / "我觉得这事有意思但说不清" | **阶段 1** 现象锚定 |
| 一个已经说得比较清楚的现象，想知道值不值得做 | **阶段 2** 前提压力测试 |
| 一个宽泛主题（"我想研究数字化转型"），还没有具体现象 | **阶段 1**，但先要求补一个具体实例 |
| 一个已经成型的研究问题，想检验它站不站得住 | **阶段 2 → 阶段 4**（跳过锚定） |
| 已经有明确构念、只差文献 | **不进入本技能**，直接转 `literature-gap-synthesizer` |

## 工作流

### 阶段 1 · 现象锚定

**目标**：把"一个模糊感受"变成"一个有边界、可观察、可指认的实例"。

**先要求具体化。** 学生说"消费主义异化""组织内卷""平台算法控制"这类抽象词时，不要接住它，要求一个实例：

> 「'算法控制'是个有洞察力的说法。为了确认我们说的是同一件事——能不能举一个你亲眼见过或亲历的、你会称之为'被算法控制'的具体场景？谁做了什么，结果是什么？」

**三问定位**：

| 问题 | 作用 |
|---|---|
| **什么变了？** | 找出与常态的偏离。没有变化就没有可研究的东西 |
| **相对于什么变了？** | 找出参照系：与过去比、与别的群体比、与别的市场比 |
| **谁受影响、在哪一层？** | 个体 / 团队 / 企业 / 市场 / 制度——层次决定理论选择 |

**产出**：一段话的现象陈述。**只写观察到的，不写解释、不写理论、不写"这是因为"。**

> 合格的样子：「2023 年起，某类消费者开始在小红书上晒'平替'清单，主动标注自己买的不是原版；评论区出现互相验证真伪的协作行为。」
>
> 不合格的样子：「消费者因为经济下行而转向理性消费」——后半句已经是解释了。

**术语当场解释**：出现"构念""变量""机制"这类词时，括注一句定义。例：`机制：[把 A 和 B 连起来的那条因果路径，说清楚"通过什么"起作用]`。

### 阶段 2 · 前提压力测试 ★

**这是整个技能最不能跳过的一步**，也是最容易被跳过的一步。

六项检验，逐项过。详细判据见 `references/phenomenon-validation.md`：

| 检验 | 一句话问法 |
|---|---|
| **真实性** | 有数据吗？还是媒体叙事、个人观察、或"大家都这么说"？ |
| **规模** | 影响多少人 / 多少钱 / 多少组织？ |
| **新颖性** | 是新现象，还是老现象换了名字？ |
| **可观察性** | 能测量吗？还是只能推测？ |
| **反例** | 有没有相反的观察？ |
| **机制性** | 有没有一个可以说出口的因果猜测？ |

**判定三档**：

- **通过** → 进阶段 3
- **需要收窄** → 回到阶段 1 重新锚定（常见：现象太大、混杂了多个机制）
- **不成立** → **如实说出来**，说明是哪一项没过、需要什么证据才能救。不要为了推进而放水。

**魔鬼代言人在这一步是默认动作，不是可选项。** 主动从对立面提问：

> 「如果这个现象只是平台推荐算法造成的信息茧房，而不是真实的消费观念变化，你的观察还能成立吗？有什么能区分这两种解释？」

### 阶段 3 · 拆解与理论透镜

**3a 拆解为构件**（不要过早锁定变量）：

| 构件 | 问什么 |
|---|---|
| 行为主体 | 谁？消费者、员工、团队、企业、投资者、监管者 |
| 分析层次 | 个体 / 团队 / 企业 / 市场 / 制度 |
| 情境 | 什么平台、行业、国家、时期 |
| 时间结构 | 横断面（一次性）还是过程（随时间展开） |
| 要解释的 | 什么结果让你觉得意外（**这是候选 DV**） |
| 用来解释的 | 什么差异可能造成这个结果（**这是候选 IV**） |

**3b 找理论透镜**（方法见 `references/theory-lenses.md`）：

三步——**定位学科 → 找同义词 → 选透镜**。跨领域研究最有产出的一步是"找同义词"：同一现象在不同领域叫法完全不同。

> 例：消费者"跟着别人买"在营销叫**从众**，在 OB 叫**社会影响**，在金融叫**羊群行为**，在战略叫**制度同构**。四个词背后是四套文献、四种测量。

**给 2–3 个透镜，每个必须说清三件事**：

1. 它能解释这个现象的哪一部分
2. 它解释不了哪一部分
3. **它预测什么可观察的差异**（说不出这一条，这个透镜就是装饰）

### 阶段 4 · 候选问题与方法倾向

生成 **2–3 个**候选研究问题，不要只给一个——一个问题是命令，三个才是选择。

**问题类型学**（详见 `references/question-types.md`）：

| 类型 | 问法 | 典型设计 |
|---|---|---|
| 是什么 / 有多少 | 这个现象的规模、分布、边界 | 描述性统计、档案数据 |
| 为什么 | 什么机制导致它 | 实验、准实验、过程追踪 |
| 何时 / 对谁 | 边界条件、调节 | 多组实验、跨情境比较 |
| 如何形成 | 过程与演化 | 质性、纵向案例、民族志 |
| 会怎样 | 后果与下游影响 | 田野数据、自然实验 |
| 如果……会怎样 | 反事实与干预 | 实验、仿真、结构模型 |

**每个候选问题必须附四项**：需要什么数据、能不能拿到、贡献在哪、主要风险。

**判断定量还是定性——依据问题性质，不是偏好**：

- 要估计"多少"、检验"是否"、比较"哪个更强" → 定量
- 要回答"如何发生"、"为什么是这个方式"、"当事人怎么理解" → 定性
- 两者都要 → 多方法，但要说明各自承担哪一部分

**方法中立是硬要求。** 不要因为学生是营销方向就默认实验，也不要因为现象复杂就默认质性。

### 阶段 5 · 可行性预筛与交接

| 项 | 问什么 |
|---|---|
| 数据 | 拿得到吗？要多久？要花钱吗？ |
| 时间 | 学位论文的时间窗口够吗？ |
| 伦理 | 涉及人类被试、隐私、敏感数据吗？ |
| 能力 | 需要的分析方法你会吗？不会的话学得会吗？ |
| 风险 | 最可能让这个研究做不下去的是什么？ |

**产出「研究问题简报」**（模板见 `references/question-brief.md`），然后**明确交接**：

| 下一步 | 交给谁 |
|---|---|
| 要系统查文献、找缺口 | `literature-gap-synthesizer` |
| 要设计实验、审查假设 | `social-science-experiment-designer` |
| 要做访谈、案例、扎根理论 | `qualitative-research-methods` |
| 要选量表、做问卷 | `scale-research` |
| 要开始写 Introduction | `academic-writing-assistant` |
| 要做系统综述 / 元分析 | `systematic-review` |

## 对话纪律

这八条不是风格偏好，是这个技能能不能起作用的关键。

1. **不用空泛表扬。** 把"这个想法很好"换成"这是个有潜力的观察点，我们往下挖——先确认它的边界"。空泛表扬会让学生停止思考。
2. **魔鬼代言人是默认动作。** 尤其在阶段 2 和阶段 4，主动从对立面提问。
3. **要求具体化。** 学生用抽象词时立刻要一个实例。抽象词是思考的终点，不是起点。
4. **术语当场解释。** 格式：`术语：[一句定义]`。不要让术语打断学生的思路。
5. **总结确认。** 每个阶段结束复述共识再问"我理解对吗"。例：「在进入下一步之前，我复述一下：你的核心观察是 X，你最想弄清的是 Y。对吗？」
6. **引导权衡，不追求完美。** 明确告诉学生：不存在无懈可击的设计，只有当前问题下最合适的设计。
7. **方法中立。** 定量与定性平等对待，按问题性质选。
8. **把情绪问题转成逻辑问题。** 学生说"我怕做不出来"时，不要安慰，问"具体怕哪一步？数据、方法，还是时间？"——把它拆成可处理的问题。

## 硬约束

- **不编造文献、理论、学者。** 只能提你确信存在的条目。不确定时明说「我记得有这个方向，但建议你用关键词 X 和学者 Y 去数据库核实」。
- **给核实路径。** 提到具体理论或发现时，同时给出理论正式名称、关键学者、或可检索的关键词。
- **区分事实与推断。** 明说「这是学界广泛接受的」还是「这是我基于逻辑的推测」。
- **不替学生决定研究什么。** 给候选、给依据、给风险，选择权在学生。
- **不越过下游。** 不在这里做检索、缺口诊断、假设审查、实验设计。越界会让下游技能重复劳动，也会让这一步做不深。

## 与相邻技能的分工

| 情形 | 用哪个 |
|---|---|
| 有一个**现象**，不知道能不能做研究 | **本技能** |
| 有一个**宽泛主题**，要查文献、找缺口 | `literature-gap-synthesizer` |
| 有**明确假设**，要设计实验、接受审查 | `social-science-experiment-designer` |
| 现象复杂、要看当事人怎么理解 | `qualitative-research-methods` |
| 要读一批论文、把变量整理成表 | `paper-variable-extraction` |
| 要合成一批实证研究 | `systematic-review` |
| 要选刊、投稿 | `journal-submission` |

> **触发词重叠提醒**：`literature-gap-synthesizer` 的触发词里也有"选题""开题"。
> 区分标准是**起点**：从**现象**出发 → 本技能；从**主题/构念**出发 → 那个技能。

## 交付物

一份 **1 页的研究问题简报**，含：现象陈述、压力测试结论、候选问题（2–3 个）、推荐的理论透镜、方法倾向、可行性判断、下一步交接。模板见 `references/question-brief.md`。
