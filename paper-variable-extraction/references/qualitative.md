# 分支 D · 质性方法 / Qualitative Methods

适用于访谈、焦点小组、民族志、扎根理论、现象学、案例研究、内容分析、主题分析、开放式编码、话语分析等研究。质性研究中的"变量"通常表现为**构念（construct）、主题（theme）、类别（category）、编码（code）**，提取方式与前三类不同。

## 提取范围

**核心构念/主题 → 数据收集方式 → 分析程序 → 编码方案 → 效度保障**

## 字段清单

### 1. 构念 / 主题 / 编码（对应"变量"）

- **名称 / 名称（EN）**：主题名或构念名（中文 + 英文原文）
- **类型**：主题 theme / 类别 category / 构念 construct / 一阶概念 / 二阶主题 / 聚合维度
- **概念性定义 / Conceptual Definition**：作者对该主题的界定（原文 + 中文翻译）
- **描述 / Description**：该主题涵盖内容的说明
- **频次 / 代表性**：出现次数、提及该主题的受访者数（文中给出时报告）
- **代表性引语 / Representative Quotes**：**逐字引用原文引语** + 中文翻译，并附受访者编号（如 "P12, female, 34"）
- **来源 / Source**：若主题来自既有理论（先验编码）还是从数据涌现（开放编码），注明

### 2. 数据来源与取样

- **样本 / Sample**：n、招募方式、抽样策略（目的性抽样、理论抽样、滚雪球）
- **样本构成**：性别、年龄、职业等关键特征
- ** saturation**：是否说明达到理论饱和及如何判断
- **数据形式**：访谈录音、转录文本、现场笔记、图片、网络帖子、档案文件
- **收集时间 / 场景**：何时何地收集、时长（如"平均 45 分钟半结构化访谈"）

### 3. 数据收集工具

- **访谈提纲 / Interview Guide**：**逐字列出提纲问题**（中英对照），包括开场问题、主问题、追问
- **焦点小组脚本**：主持人指引、讨论话题顺序
- **观察框架**：民族志的观察维度清单

### 4. 分析程序 / Analysis Procedure

- **分析方法**：扎根理论（开放式/主轴/选择性编码）、主题分析（Braun & Clarke 六步）、内容分析、话语分析、常比较法
- **步骤 / Steps**：分步骤描述分析流程
- **编码者**：人数、是否独立编码、分歧如何解决（协商 / 第三方仲裁）
- **软件**：NVivo、ATLAS.ti、MAXQDA 或手工编码

### 5. 编码方案与信度

- **编码本 / Codebook**：主要编码及其定义（可做成表：编码名、定义、纳入/排除标准、示例引语）
- **编码者间信度 / Inter-coder Reliability**：具体指标与数值（如 Cohen's κ = .81、Krippendorff's α = .76、percent agreement = 92%）；**若作者未报告，写「原文未提供」**
- **效度保障 / Trustworthiness**：成员核查（member checking）、三角验证、审计追踪、反例分析、厚描（thick description）

### 6. 混合编码（质性 + 量化）

若研究把质性编码转为计数或变量（如"某主题是否出现 → 0/1 编码"），按二手数据分支补：编码规则、编码者信度、变量构造方式。

## 输出格式示例

```markdown
### 主题 / Theme：品牌回避 / Brand Avoidance（二阶主题）

**概念性定义 / Conceptual Definition**
> "…" —— 原文引用 + 中文翻译

**一阶概念 / First-order Concepts**：质量担忧、价值观冲突、身份表达
**代表性引语 / Representative Quotes**
> "I stopped buying from them after…" (P07, male, 29) —— "在他们……之后我就不再购买了。"

**频次 / Frequency**：提及该主题的受访者 18/24
**来源 / Source**：从数据涌现（open coding），非先验编码
```

## 7. 系统性 / 整合性文献综述 · Systematic or Integrative Literature Review（理论构建型）

管理学期刊常见「先用整合性综述构建理论，再用多个研究检验」。综述本身是**一个独立的数据收集单元**，要单独编码——它的"数据"是**文献与段落**，不是受访者。不要因为"没有样本"就跳过。

### 字段清单

| 字段 | 说明 |
|---|---|
| **检索来源 / Databases** | 具体数据库名（如 EBSCO Academic Search Premier、JSTOR、Web of Science、PsycINFO） |
| **检索式 / Search Terms** | **逐字记录检索词与组合逻辑**（如 `religio*` AND `sex` OR `gender` AND 各宗教名）；布尔逻辑与通配符照抄 |
| **纳入 / 排除标准** | 时间范围（如「仅 21 世纪文章」）、语言、文献类型、主题相关性 |
| **纳入规模** | 纳入文献数（如 133 篇）、**编码段落数**（如 1,041 段）、每个子类的覆盖度（如「每个世界宗教至少 34 篇，44% 的文章讨论多个宗教」） |
| **编码程序** | 分步骤：谁初筛 → 谁标注 → 如何迭代形成编码方案 → 谁继续编码 → 何时停止 |
| **理论饱和判据** | 如何判断饱和（如「分析新增段落不再产生新见解」，引用 Glaser & Strauss） |
| **编码方案 / Codebook** | 主题/维度名 + 定义 + 纳入标准 + 代表性引语 |
| **编码者间信度** | **若未报告，明确写「原文未提供」**——综述型论文漏报信度极常见，不要替作者补 |
| **跨来源三角验证** | 是否要求主题在多个子类（如多个宗教、多个情境）中都出现，以证明维度可复制 |
| **反身性 / Reflexivity** | 是否说明研究者立场与反身性处理 |
| **输出物** | 主题表（如 Table 1）的结构：行/列分别是什么，每格放什么（如「每个宗教 × 每个维度各放一条逐字引语」） |

### 综述产出的构念如何进入 Variables 表

综述提炼出的维度（如「社会领域分化」「性分化」「能动性分化」）本身就是**构念**，应作为变量录入，角色标 `Target Construct` 或按其在后续研究中的作用标 `Mediator` / `IV`。字段填法：

- `conceptual_definition`：综述中给出的定义原文 + 中文
- `operationalization`：先填「理论构建阶段：由文献综述提炼」，再在各实证研究中填具体操作化
- `source_apa`：综述的引语来源（Table 1 中每条引语的出处），而非量表出处
- `reliability_value`：综述未报告编码者间信度时写 `原文未提供`

### 输出格式示例

```markdown
### 数据收集单元：整合性文献综述 / Integrative Literature Review

**目标 / Purpose**：通过对宗教与性别文献的系统性整合，提炼跨宗教共通的性别分化维度

**检索策略 / Search Strategy**
- 数据库：EBSCO Academic Search Premier、JSTOR
- 检索式：`religio*` AND (`sex` OR `gender`) AND [Buddhism, Christianity, Folk, Hinduism, Islam, Judaism]
- 纳入标准：21 世纪发表的文章；按 Pew Research Center (2014) 的六大宗教确保代表性

**规模 / Corpus**：133 篇文章、1,041 个段落；每个宗教至少 34 篇；44% 的文章讨论多个宗教

**分析程序 / Procedure**
1. 第一作者阅读文献并标注涉及性别的段落
2. 两位作者迭代识别主题、形成编码方案
3. 第一作者继续编码直至理论饱和（Glaser & Strauss, 2017）
4. 检验每个主题是否跨宗教出现，以保证维度可复制
5. 全程保持反身性（Charmaz, 2006）

**编码者间信度 / Inter-coder Reliability**：原文未提供
**输出 / Output**：Table 1（六大宗教 × 四个维度的逐字引语矩阵）
```

## 8. 民族志 / 田野研究 · Ethnography & Fieldwork（含网络民族志）

民族志论文的"变量"几乎全是**主题与构念**，且数据结构是**树**（核心构念 → 标记/维度 → 机制 → 一阶概念）。提取时有四条硬性要求。

### 8.1 主题层级必须建树，不能平铺

Variables 表用 `parent_theme` + `theme_level` 两列表达嵌套：

| `theme_level` | 含义 |
|---|---|
| `Core construct` | 论文提出/研究的核心构念（如 Brand Community） |
| `Marker` / `Aggregate dimension` | 构念下的顶层维度（如社群三标记、聚合维度） |
| `Second-order theme` | 维度下的机制或过程（如 Legitimacy、Oppositional Brand Loyalty） |
| `First-order concept` | 受访者原话层面的类别（如「odyssey story」「saved my life story」） |
| `Code` | 最细粒度的开放编码 |

- `parent_theme` 必须**与上级行的 `variable_name_en` 完全一致**（大小写敏感）——脚本会做断链检查
- 报告里先给一张**缩进的层级树**，再逐层展开，不要按字母或出现顺序平铺
- 层级树本身就是这类论文的"数据结构图"（对应量化论文的 Table 1），**必须在报告中画出**

### 8.2 田野点清单（field sites）

民族志的"样本"不是一个 n，而是一组田野点。每个点记录：地点/社群名 → 类型 → 收集方式 → 时长/规模 → 研究者在场方式。

| 田野点 | 类型 | 收集方式 | 规模 |
|---|---|---|---|
| Fairlawn 街区 | 居住社区 | 家庭访谈 + 参与观察 | 4 户 / 9 人 / 110 小时 |
| Smith Motors | 品牌经销商 | 非参与观察 + 现场访谈 | 5 次到访 / 25 小时 |
| Midwest Saab Club | 品牌俱乐部 | 参会观察 + 个人与小组访谈 | 2 次会议 / 8 小时 |
| WWW（Yahoo / HotBot 检索） | 计算机中介环境 | 网页下载与文本分析 | 50+ 站点 / 300+ 页 |

对应的 Excel 字段：`field_sites`（列表）、`data_volume`（数据量）、`sampling_strategy`。

### 8.3 数据量 ≠ 样本量

民族志常报**小时数 / 页数 / 帖子数 / 转录页数**而不是人数。`n` 与 `data_volume` 必须**分开填**：

- `n`：受访人数（如 `9`）
- `data_volume`：访谈与观察 110 小时 / 300+ 页网页 / 208 页转录稿

只写一个会让人误以为有 110 个受访者。**观察为主的田野点（如经销商、俱乐部）人数常未单独报告，写 `NA` 并在 `notes` 说明。**

### 8.4 研究者立场与反身性（`researcher_positionality`）

民族志的效度很大程度建立在研究者立场上，必须记录：

- **在场方式**：参与式观察者 / 非参与观察者 / 完全参与者
- **局内-局外身份**：研究者本人是否就是社群成员（emic）。若作者自己是成员（如本文第二作者是 Saab 社群成员），这是一条**关键效度信息**，不是八卦
- **多人视角**：几位研究者、视角是否不同、是否用分歧做解释性张力（investigator triangulation）
- **进入方式**：如何获得准入（熟人引荐 / 守门人 / 公开活动）

### 8.5 没有假设时用「研究目标」

民族志、扎根理论、案例研究**常常通篇没有 H1/H2**，只有 "the study had four major objectives"。此时：

- Hypotheses 表**不要留空**，改成逐条记录研究目标
- `hypothesis_id` 写 `Objective-1`、`Objective-2`…；`test_type` 写 `Objective`
- `supported` 用**质性口径**：`Observed`（在数据中观察到）/ `Partially observed` / `Not observed`，**不要写 `Supported`** —— 质性研究不检验假设，只论证现象存在
- `statistic` / `p_value` / `effect_size` 一律 `NA`；证据写在 `hypothesis_cn` 或 `note` 里（如「以三个品牌社群的田野数据论证」）

### 8.6 伦理与匿名化

- 是否使用**化名**（受访者与地名）。本文受访者（Bob、Jill…）与地名（Bloomingdale、Fairlawn）**均为化名**，要在 Studies 表 `notes` 与报告里点明——否则复现者会去找一个不存在的镇
- 知情同意、IRB 批准、数据来源公开性（网页是公开数据还是需登录的私域）

## 常见遗漏点（务必检查）

- 附录中的完整访谈提纲（interview guide / discussion guide）
- 数据表里的编码结构图（一阶概念 → 二阶主题 → 聚合维度）
- 编码者间信度的具体数值（常只在方法脚注里提一句）
- 预测试（pilot interview）与正式样本的区别
- 引语的受访者编号与人口学标注
- **附录里的受访者/家庭档案**（本文的 Appendix 描述了 4 户参与家庭，是样本构成的核心来源）
- **田野点清单与各自时长**（常散落在正文"研究场景"段落，不在方法小节）
- **研究者自己的成员身份**（作者是社群成员时，常写在方法脚注或致谢里）
- **化名声明**（受访者名、地名是否化名）
- **访谈提问的实际措辞**（本文只说"questions dealt with general consumption habits…"，未给逐字提纲 → 写「原文未提供」）
