# 分支 G · 计算测量法 / Computational Measurement

适用于**用机器学习模型作为测量工具**的研究：图像分类、文本分类、音频/视频分析、行为日志挖掘、
人脸/表情识别、地理影像判读等。判定线索：论文里出现 "we train a model"、"convolutional neural network"、
"fine-tune"、"out-of-sample accuracy"、"AUC"、"human coders vs model"、"ground truth labels"。

> **与 C（二手数据）的分界**：C 回答「数据从哪来」，G 回答「**测量工具怎么造**」。
> 一篇论文可以同时属于两者——本文用 Instagram 的图（C）喂给自训的分类器（G）。
> 判定时问一句：**如果换一批同类数据，结论还成立吗？** 成立 → C；不成立、因为尺子是新造的 → G。

---

## 一、先判断它属于哪种"用模型"

| 类型 | 特征 | 提取重点 |
|---|---|---|
| **自训模型（本分支主体）** | 作者收集标注数据、训练并验证自己的模型 | 训练数据、划分、性能、人类对照 |
| **调用已有模型/API** | 直接用 GPT / CLIP / 商用情感 API | 模型版本、提示词或参数、抽样人工校验 |
| **已有词典/规则** | LIWC、情感词典、正则匹配 | 词典版本、覆盖率、人工校验比例 |

> 三者的共同要求：**必须有人工校验**。调用现成 API 不等于免检——模型版本会变，
> 领域迁移会失效，必须抽样比对并报告一致率。

## 二、三阶段提取（开发 / 验证 / 应用）

### 2.1 开发阶段：模型是怎么训练出来的

| 项 | 要求 | 缺失后果 |
|---|---|---|
| **训练数据来源** | 平台、检索方式、抓取时点 | 无法判断训练域与目标域是否同分布 |
| **标注方式** | 谁标的、标了多少、如何保证质量（专家/众包/关键词检索/既有标签） | 标签噪声直接决定性能上限 |
| **正例怎么来** | 如「属性词检索取前 2,000 张」 | 复现不了 |
| **负例怎么来** | **最容易漏的一项**。如「反义词检索」「其他类别的样本」「随机负采样」 | 负例构造决定模型学到什么，不报等于方法不完整 |
| **样本量与类别平衡** | 总数、每类多少、是否平衡 | 不平衡时 accuracy 会骗人（见红线 1） |
| **数据划分** | 训练 / 验证 / 留出的**比例与规模**；划分单位（图像/用户/时间） | 用测试集调超参 → 性能虚高 |
| **基座与架构** | 从什么模型微调（如 CaffeNet）、网络结构、损失函数 | 无法判断方法先进性 |
| **超参数与选择依据** | 学习率、批大小、轮数；**依据验证集还是拍脑袋** | 同上 |

> **划分单位比比例更重要。** 按图像随机划分会让同一用户的相似图跨训练/测试集，性能虚高；
> 按用户或按时间划分才是真外推。论文没写划分单位时，必须列入缺口清单。

### 2.2 验证阶段：凭什么说这个模型可信

三条证据，**缺一不可**：

**① 内部性能**：不能只报 accuracy。

| 指标 | 什么时候必须报 |
|---|---|
| **AUC / ROC** | 类别不平衡时（几乎总是）——accuracy 会被多数类吃掉 |
| **Precision / Recall / F1** | 关心某一类错误代价时（如漏检违规内容） |
| **校准（calibration）** | 模型的概率要被当作连续变量用（如取均值当指标） |

**② 与人类对照**：这是最容易被糊弄的一环。

> 只报「模型与人类一致率 85%」是没有意义的——**没有基准，85% 是高是低无从判断**。
> 必须同时给出**单个人类标注者 vs 多数投票**的一致率作为参照。
>
> 正确写法（可照抄的结构）：
> 「模型 vs 人类多数：一致率 82.5%；单个人工标注者 vs 多数：82%。
> 即模型的判断水平与一名普通人类标注者相当。」
>
> 还要报**人类之间本身的分歧程度**（如"600 张图里只有 7 张获得 20 人全票一致"）。
> 人类分歧越大，模型的上限就越低——这不是模型的问题，是任务本身模糊。

**③ 与传统方法的基线比较**：深度学习不是免死金牌。

- 与特征工程 + 传统分类器（SVM、随机森林、逻辑回归）比；
- 与最简单的基线（多数类、词典法）比；
- 若深度学习没有显著优于简单方法，**要在报告里说出来**，不能只报最好看的那个。

**分组检验**：把样本按模型预测概率分成「高 / 接近 50% / 低」三组分别看一致率。
模糊组一致率低是正常的；若模糊组以外也低，模型就有问题。

### 2.3 应用阶段：从模型输出到构念

| 项 | 要求 |
|---|---|
| **目标域** | 训练域与目标域是否同一平台/人群/时期；跨域时有没有做迁移验证 |
| **去噪规则** | 剔除垃圾、广告、机器账号、官方账号的具体规则与数量 |
| **聚合方式** | 图像层概率 → 品牌/用户层指标，用**均值、中位数还是分位数**？为什么 |
| **收敛效度** | 与已有的测量（调查、行为指标、专家评分）比对，报相关与显著性 |
| **可解释性边界** | 若研究问题涉及"为什么"，深度学习答不了（见红线 6） |

> **聚合方式是研究者的选择，不是技术细节。** 均值会被极端图拉偏，中位数对少量强信号不敏感。
> 论文只写「取平均」时，要记录这一点并说明未做其他聚合的敏感性检验。

## 三、字段清单（映射到 Excel）

| 字段 | 所在表 | 填什么 |
|---|---|---|
| `method_type` | Studies | `Computational Measurement` |
| `model_spec` | Studies | 架构 + 基座 + 关键超参，如「多标签 CNN，CaffeNet 微调，学习率 .0001」 |
| `train_n` / `val_n` / `holdout_n` | Studies | 三个划分的规模（整数），比例写进 `model_spec` 或 `notes` |
| `model_metrics` | Studies | 汇总性能，如「留出集准确率 90%，平均 AUC .85」 |
| `n` + `n_unit` | Studies | **必须带单位**：`16,368` + `图像`；不要只写数字 |
| `variable_type` | Variables | `Model-predicted`（自训模型）/ `Automated image` / `Automated text` |
| `model_performance` | Variables | **该构念上**的模型指标，如「accuracy 88.6%, AUC .846」 |
| `validation_agreement` | Variables | 与外部基准的一致性，如「vs 人类多数 AUC .93、一致率 83%」 |
| `measurement_model` | Variables | **只放 CFA / 测量模型拟合**，不要塞分类器性能 |
| `reliability_type` / `reliability_value` | Variables | 只放 α/CR/κ/ω；AUC 与一致率放 `model_performance` |

> **`n` 的四种语义别混**：训练图数、判断条数、目标域图数、受访者人数。
> 多方法论文里这四种常同时出现，每个研究行的 `n` 必须配 `n_unit`。

## 四、六条红线（写进报告前逐条检查）

1. **只报 accuracy 不给 AUC** → 类别不平衡时无法判断。必须补 AUC 或 P/R/F1。
2. **没有人类基准** → 「一致率 85%」无意义。必须给"单个人类标注者 vs 多数"作参照。
3. **不报负例怎么构造** → 方法不完整。正例容易，负例才是设计难点。
4. **不报数据划分** → 若用测试集调超参，性能虚高。必须报 train/val/holdout 的规模与单位。
5. **跨域不做验证** → 训练域（如 Flickr）与目标域（如 Instagram）不同分布时，
   必须在目标域上重验，不能假设可迁移。
6. **把模型输出当成构念本身** → 模型测的是"图像里有没有这个属性"，
   不是"消费者怎么感知"。后者要靠收敛效度（与调查/行为数据比对）来支撑。

## 五、常见遗漏点

- **标注者资质与培训**：众包平台的等级（如 Figure Eight 的 Level 3）、是否给指导语、是否做预试。
- **标注成本**：条数与单价常写在脚注里（如「12,000 条，$288.96，单条 $0.024」），是复现难度的信号。
- **类别的语义边界**：本文用"属性词 vs 反义词"界定边界，这本身就是操作化定义，要逐字记录配对关系。
- **多标签 vs 多类别**：一张图可同时有多个属性（多标签）与只能选一个（多类别），
  影响损失函数与评估方式，要写清。
- **类别不均衡的处理**：过采样、加权损失、阈值调整——调过阈值就要报原始分布。
- **模型版本与随机种子**：深度学习结果有随机性，报不报种子影响可复现性。
- **代码/权重/数据是否公开**：不公开就在缺口清单里写明「不可复现」。
- **训练集是否含目标品牌**：若训练图里已出现被测品牌，等于信息泄漏。

## 六、与相邻分支的关系

| 分支 | 关系 |
|---|---|
| C 二手数据 | 常同时成立。C 记数据来源，G 记测量工具；两套字段都要填 |
| B 问卷 | 计算测量常需要问卷做收敛效度（如与品牌感知调查比对）→ 该调查单独占一个研究行 |
| A 实验 | 若模型输出被用作实验的因变量，两套字段都要填 |
| F 元分析 | 用计算测量编码调节变量时，`coding_source` 写 `Automated text`；图像类暂记 `Automated image` 并在 notes 说明 |

## 七、输出格式示例（片段）

```markdown
### S1 · 模型训练（计算测量）

| 项 | 内容 |
|---|---|
| 训练数据 | Flickr 检索结果（4 属性词 + 4 反义词，各约 2,000 张） |
| 负例构造 | 反义词检索 + 其他属性图像补充 |
| 规模 | 16,368 张，每张 4 个二值标签 |
| 划分 | 80% 训练 / 10% 验证 / 10% 留出 |
| 模型 | 多标签 CNN，CaffeNet 微调，学习率 .0001 |

**留出集性能**

| 构念 | accuracy | AUC | 与人类一致率 | 单个人类 vs 多数 |
|---|---|---|---|---|
| Glamorous | 88.6% | .846 | 83% | 85% |
| Rugged | 91.3% | .853 | 85% | 83% |
```

> 最后两列是**判定效度的关键**：模型与人类一致率略高于单个人类与多数的一致率，
> 说明模型达到了"一名合格人类标注者"的水平；若明显低于，就该质疑模型。
